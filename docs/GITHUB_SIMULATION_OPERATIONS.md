# GitHub 시뮬레이션 게시 운영

GitHub 관리팀은 검증이 끝난 코드와 시뮬레이션 결과를 `jaesung0804/st_dashboard`에 게시한다. 사용자는 2026-09-10 공개 저장소의 정상 실행 결과물 커밋과 기존 GitHub Pages 게시를 승인했다. 새로운 유료 서비스, 유료 API, 원격 AI 호출을 추가하지 않는다.

## 게시 단위와 검증

1. 실행이 끝난 버전의 코드·정책·입력 해시·결과를 고정한다. 실행 중인 작업 디렉터리를 그대로 업로드하지 않는다.
2. 미래 정보 사용 방지, 거래 시점, 수수료, 현금 보존, 보유가격 누락 처리를 확인하는 검사를 통과해야 한다. 결과 수익률이 낮아도 연구 기록은 보존한다.
3. 결과 디렉터리의 `manifest.json`에 있는 파일 해시를 대조한다. 실행 후의 코드 정리로 파일 해시가 달라지면 실행 당시 해시를 고치지 말고 차이를 기록한다.
4. 회사별 수익률을 게시할 때 비교 기간, 초기 자본, 비용 가정, 비교 대상, 표본 선정 편향과 미해결 가격 누락을 함께 표시한다. 전체 결과를 이미 본 뒤 고친 규칙은 독립적인 미사용 검증으로 표현하지 않는다.
5. 페이지의 JSON·JavaScript 구문, 데이터 참조, 필요한 정적 파일을 확인하고 게시 후 URL과 버전을 확인한다.

## 용량과 기록 보존

- 원가격 CSV, 개인 캐시, 전체 데이터 복제본은 코드 브랜치에 올리지 않는다. 기존 `dashboard-state` 원본의 위치·커밋·해시를 기록한다.
- 상세 거래·결정·NAV 원장은 gzip으로 압축한다. 웹 첫 화면에는 요약과 필요한 시계열만 배포한다.
- 게시 전 변경 파일 총량과 최대 단일 파일 크기를 확인한다. 큰 파일은 중복 여부와 필요성을 검토한 다음 기존 저장 구조에 맞게 분리한다.
- 한 실험 버전의 원장을 다른 실행 결과로 덮어쓰지 않는다. 새 실험은 새 버전 디렉터리로 추가한다.
- 기존 커밋, 다른 팀의 파일, 기존 시장 페이지를 삭제하거나 강제 덮어쓰지 않는다. `force push`, orphan 브랜치로 기존 Pages 이력을 교체하는 게시 방식은 사용하지 않는다.

## 인증 및 충돌 처리

Git CLI에 인증정보가 없으면 연결된 GitHub 앱의 Git 데이터 도구로 게시할 수 있다. 비밀값을 조회하거나 로그에 출력할 필요가 없다.

1. 대상 브랜치의 현재 커밋과 트리를 조회한다.
2. 고정한 스냅샷의 변경 파일만 blob으로 생성하고, 반환된 Git blob SHA를 로컬 내용의 SHA와 대조한다.
3. 현재 트리를 바탕으로 변경 경로만 덮은 새 트리를 만든다. 현재 커밋을 부모로 새 커밋을 만든다.
4. 브랜치를 다시 읽어 다른 변경이 없는지 확인하고 `force=false`로 갱신한다. 진행 중 브랜치가 바뀌었으면 새 기준에서 차이를 확인하고 다시 합친다.
5. 원격 트리의 각 게시 경로와 SHA를 확인한다. 게시 커밋 URL, 파일 수·용량, 검사 결과를 Trello 관리 카드에 남긴다.

공유 로컬 저장소에서 다른 팀이 작업하는 동안 관리팀은 `checkout`, `reset`, index 변경이나 로컬 커밋을 하지 않는다. 별도 스냅샷에서 검증하고 원격 게시를 담당한다.

## GitHub Pages

시뮬레이션 화면은 기존 Pages의 `simulation/` 경로를 사용한다. 앱 코드의 페이지 생성 절차에도 같은 파일을 포함해 이후 정상 배포에서 유지되도록 한다. 직접 게시할 때는 최신 `gh-pages` 트리에 시뮬레이션 관련 파일만 추가하는 커밋으로 갱신하고 기존 경로와 이력을 보존한다. 장시간 실험 중에는 검증한 중간 결과와 최종 결과를 구분해 게시한다.

## V1 게시 확인

- 고정 스냅샷: 로컬 커밋 `72d9d0ee33515b98fd48e95eb6c053a4708ffdcb`.
- 시뮬레이션 변경 파일: 23개, 합계 3,224,652 bytes, 최대 954,613 bytes. 대용량 원가격 파일 없음.
- 고정한 V1 코드에서 4개 핵심 검사 통과.
- V1 원장 12개의 SHA256, 업로드한 23개 blob SHA가 모두 일치했다. 원격 전체 tree `892a3104a74c908685a64c0c16e5e5306c55041e`는 고정 스냅샷의 tree와 동일하다.
- 공개 게시 완료: [7fd8514dff53ced690d1f81f597a6786eae8004c](https://github.com/jaesung0804/st_dashboard/commit/7fd8514dff53ced690d1f81f597a6786eae8004c). 기존 main `18ef38193dd526b80db671e588386bf8ea968590`을 부모로 연결하고 비강제로 갱신했다.
- V1 실행 manifest는 실행 당시 runner 해시를 보존한다. 실행 뒤 사용하지 않는 import를 정리한 코드와 해시가 다를 수 있으며 원장 해시는 변경하지 않는다.
- 게시 커밋과 최종 배포 상태는 Trello의 `[GitHub 관리팀] 검증 결과·용량·배포 관리` 카드에서 관리한다.

## Pages 게시기 검증

`python scripts/test_pages_publish_local.py`는 실제 게시 함수를 임시 로컬 Git 원격에 실행한다. 외부 네트워크나 공유 저장소 index를 사용하지 않는다. 기존 커밋 이력과 다른 팀의 `research/`·시뮬레이션 이전 기록 보존, 이번에 만들지 않은 시장 폴더 보존, 완전히 재생성한 시장 폴더의 기간 제한, 동일 결과 재게시 시 무변경, 다른 팀이 먼저 게시하면 비강제 push 거부를 확인한다.
