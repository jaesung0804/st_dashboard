# 한국 상승 AUC·시장별 배치·미국 수집 장애 점검

점검일: 2026-09-11. 대상: `jaesung0804/st_dashboard`, 운영 모델 `kr-2026-09-ews-price-v1`.

## 판단

한국 상승 모델의 **날짜를 합친 AUC 0.498은 재확인됐다. 다만 같은 날 종목을 고르는 능력까지 랜덤이라는 뜻은 아니다.** 저장 모델을 다시 평가하니 날짜별 AUC는 모두 0.568~0.688, 평균 0.642였다. 실제 문제는 날짜 사이의 확률 수준이 시장 상황과 반대로 움직인 것이다. 따라서 전체 AUC를 무시해서도, 단순히 확률의 표시 범위를 넓혀 해결했다고 주장해서도 안 된다.

미국 최근 배치의 직접 실패 원인은 **일부 종목에만 도착한 최신 날짜를 전체 시장의 기준일로 삼은 것**이었다. 액면분할·배당 등에 따른 가격 조정 문제는 별도로 존재하지만, 이 실패의 대부분을 설명하지 않는다.

Oracle 백엔드는 연결돼 있으며 운영 상태를 복원하는 데 실제 사용했다. 다만 **파일 스냅샷의 외부 저장은 운영 중이고, 모든 가격을 SQL로 조회하는 구조로의 전환은 미완료**다.

## 1. 한국 AUC의 정확한 의미와 재평가

현재 상승 목표는 단순한 익일 상승이 아니다. **126거래 관측 뒤 수익률이 20% 이상이면서, 신호일 유동성 조건을 통과한 종목군의 중앙 수익률보다 10%p 이상 높은 사건**이다. 하락 목표는 이후 63거래 관측 중 조정종가가 20% 이상 하락하는 사건이다.

9월 상승 모델은 2026-08-31을 자료 기준일로 사용했다. 실제 학습 신호일은 2022-09-06~2025-05-15, 학습 결과 관측의 마지막 날짜는 2025-11-19다. 확률 보정에 쓴 신호일은 2025-11-25~2026-02-25의 13개 주간 표본이며, 결과 관측은 2026-06-04~08-31까지다. **9월 투자 성과를 이미 평가한 수치가 아니며, 별도의 미사용 시험 구간 성적도 아니다.**

| 지표 | 저장 당시 진단 | 현재 저장 가격으로 재평가 |
|---|---:|---:|
| 보정 표본 수 | 17,704 | 17,716 |
| 실제 상승 사건 비율 | 15.352% | 15.370% |
| 날짜 통합 AUC | 0.49849 | 0.49810 |
| 상위 10% 적중률 / 전체 사건 비율 | 0.975배 | 0.973배 |
| 최종 확률 Brier 손실 | 0.13164 | 0.13177 |
| 같은 표본의 일정 확률 기준 Brier | 약 0.12995 | 0.13008 |

Brier는 낮을수록 좋다. 전체 기간의 사건 비율만 일정하게 제시하는 사후 진단 기준보다도 확률 손실이 나쁘다. 이 일정 확률은 해당 구간 결과로 계산한 비교값으로, 사전에 이용할 수 있었던 전략 성과를 뜻하지 않는다.

재평가에 쓴 모델과 트리 파일은 저장된 체크섬을 검증했다. 수치·날짜별 결과·소스 해시는 [진단 근거 JSON](MARKET_HEALTH_EVIDENCE_20260911.json)에 보존했다. [실행 기록](https://github.com/jaesung0804/st_dashboard/actions/runs/34566311033)에서도 확인할 수 있다.

**재현 한계:** 현재 가격 파일은 이후 수집·수정이 반영된 스냅샷이다. 원래 학습 카드의 전체 CSV 해시와 다르며 표본도 12행 증가했다. 원래 CSV 해시는 학습 기준일까지 자른 자료가 아니라 파일 전체의 해시이므로, 해시 차이 자체가 학습자료 훼손을 증명하지는 않는다. 이번 결과는 정확한 바이트 단위 재현이 아닌 근접 재평가이며, AUC 차이는 -0.00039다. 원본 학습 입력과 분할 표본의 별도 보존이 필요하다.

재평가 입력에는 비양수·결측 조정종가가 없었다. 다만 기업행사 공시와 전체 가격 이력을 전수 대조한 데이터 감사까지 수행한 것은 아니다.

## 2. 확인된 원인

### 날짜 사이의 확률 수준과 같은 날짜의 종목 순위가 섞였다

| 보정 신호일 | 실제 사건 비율 | 평균 원점수 | 같은 날짜 AUC |
|---|---:|---:|---:|
| 2025-11-25 | 32.75% | 13.38% | 0.629 |
| 2025-12-23 | 17.20% | 11.35% | 0.679 |
| 2026-01-23 | 9.27% | 21.67% | 0.651 |
| 2026-02-25 | 7.48% | 24.93% | 0.568 |

13개 날짜 전체의 같은 날 AUC 평균은 **0.64169**, 날짜별 상위 10% 적중률을 각 날짜의 사건 비율로 나눈 값의 평균은 **2.011배**다. 반면 날짜별 평균 원점수와 실제 사건 비율의 상관은 **-0.760**이다. 사건이 많은 날짜의 점수는 낮고, 사건이 적은 날짜의 점수는 높은 역전이 날짜 통합 AUC를 훼손한다. 날짜를 합치는 과정에서 결론이 뒤집히는 집계 문제와, 시장 시기별 확률 추정 실패가 함께 확인됐다.

재평가 표본에서 전체 양성·음성 비교 쌍의 **92.82%는 서로 다른 날짜 사이의 비교**다. 같은 날짜 쌍만 가중해 계산한 AUC는 0.64221, 서로 다른 날짜 쌍의 AUC는 0.48695다. 전체 AUC가 일별 종목 선택 성적과 달라지는 이유를 비교 쌍 단위로도 확인할 수 있다.

날짜별 지표가 좋다는 이유로 운용 가능성을 확정할 수는 없다. 13개 신호일은 126관측 뒤의 결과가 크게 겹치며 독립 표본 13개도, 독립 거래 17,716개도 아니다. 같은 날 순위 성적은 수수료·체결·급락 회피 조건을 적용한 포트폴리오 성적과도 다르다.

### 고정 50:50 결합과 시장 변화

| 구성 요소 | 학습 자료 내부 AUC | 보정 구간 통합 AUC |
|---|---:|---:|
| 로지스틱 회귀 | 0.6445 | 0.4538 |
| LightGBM | 0.7030 | 0.5341 |
| 50:50 결합 원점수 | 0.6858 | 0.4981 |
| 확률 보정 후 | 0.6858 | 0.4981 |

학습 내부 성적은 미래 성능 검증이 아니다. 보정 구간에서 로지스틱 점수의 통합 순서가 역전됐고, 고정 비중 결합 결과도 약해졌다. 그러나 같은 보정 구간을 보고 트리 100%로 바꾸면 그 구간에 맞춘 선택이 된다. 별도 시간순 검증 없이 운영 비중을 바꾸지 않는다.

입력 분포 변화도 확인됐다. 상승 모델에서 시장 폭 `breadth200` 평균은 학습 대비 **1.81 표준편차**, 종목 수익률 분산 `dispersion20`은 **1.62 표준편차**, 시장 60일 수익률은 **1.20 표준편차** 이동했다. 장기 결과의 성숙을 기다리고 학습·보정의 결과 구간을 겹치지 않게 제거하면서, 실제 학습 신호가 2025년 5월에서 끝난 점도 적응 지연을 만든다.

이 수치는 시장 변화와 적응 지연의 근거다. 각 변수가 AUC 하락에 기여한 비중까지 인과적으로 확정한 것은 아니다. 이를 확인하려면 시장 공통 변수 제외, 날짜별 동일 가중치, 학습 기간 변경 등의 통제 실험이 필요하다.

### 확률 보정의 압축은 원인보다 결과에 가깝다

보정식은 원점수 `r`과 `sigmoid(0.00434 × logit(r) - 1.70008)`를 절반씩 섞는다. 계수가 거의 0이어서 보정 성분은 사건 비율 근처의 상수로 수축한다. 양의 단조 변환이므로 원점수와 최종 점수의 순위 및 AUC는 같다. 보정이 확률 범위를 좁혔지만, 이미 사라진 날짜 통합 구분력을 회복시키지는 못한다.

현재 코드는 음의 보정 계수만 거부한다. 거의 0인 계수, 날짜별 성적과 통합 성적의 괴리, 일정 확률 기준보다 나쁜 확률 손실은 운영 판단에 반영하지 않았다. 이번 변경은 향후 새 모델 카드에 **날짜별 AUC·사건 비율·평균 확률·상위 10% 지표**를 함께 저장한다. 기존 동결 모델과 예측은 변경하지 않는다.

참고로 하락 모델은 통합 AUC 약 0.712지만, 보정 구간 사건 비율은 학습 28.4%에서 72.0%로 변했다. 하락 모델 역시 좋은 순위 성적만으로 확률의 정확성을 보장할 수 없다.

## 3. 한국 모델에서 다음으로 할 일

1. **평가와 확률 해석부터 바로잡기:** 같은 날 종목 선택과 날짜별 절대 사건 확률을 별도 지표로 관리한다. 현재 상승 점수를 검증된 투자 성공 확률로 취급하지 않는다.
2. **학습 입력을 재현 가능하게 고정:** 기준일까지의 입력, 학습·보정 행 식별자, 예측 원점수와 결과의 해시를 모델별 백엔드 스냅샷으로 보관한다. 공개 Git에는 집계 진단만 둔다.
3. **통제 실험:** 로지스틱·트리·결합을 분리하고 시장 공통 변수 제외, 날짜별 동일 가중치, 상대 순위 학습과 시장 사건 비율 추정의 분리, 학습 기간 변경을 비교한다. 학습에 사용하지 않은 과거 순차 예측으로 보정하는 방식도 평가해 현재의 긴 적응 지연을 줄일 수 있는지 확인한다.
4. **미사용 시간 구간에서 승격 판단:** 결과 관측의 중첩을 제거한 여러 시장 국면에서 날짜별 순위, 확률 손실, 비용 반영 수익률·최대낙폭을 함께 평가한다. 현재 보정 구간만 보고 비중·임계값을 고르지 않는다.

이번 점검은 원인 진단과 운영 장애 수정이다. **새 상승 모델의 성능 개선이나 투자 초과수익 달성을 주장하지 않는다.**

## 4. 미국 수집 장애와 수정

[실패 배치](https://github.com/jaesung0804/st_dashboard/actions/runs/34545753540)의 보존된 수집 기록을 확인했다.

- 요청 5,020종목, 최근 활동 종목 4,919개.
- 유효 응답 4,885종목. 각 응답의 마지막 날짜는 4,595종목이 9월 9일, 257종목이 9월 10일이었다.
- 기존 코드는 가장 늦은 9월 10일만 기준으로 삼아 `257 / 4,919 = 5.22%`로 실패 처리했다.
- 조정가격 변경 감지 28종목 중 25종목은 전체 이력 재수집 완료. `ALP`, `LFT`, `UCAR` 3종목은 전체 이력을 확보하지 못해 격리했다.
- 그 밖에 시가·고가·저가·종가 관계 이상 46건, 겹치는 이력 누락 37건, 공급 응답 없음 49건이 있었다. 이 기록만으로 모든 조정 변경을 액면분할이라고 분류할 수는 없다.

수정한 선택 규칙은 다음과 같다.

1. 최근 활동 종목이라는 **고정 분모**의 95% 이상이 실제로 있는 최신 날짜를 찾는다.
2. 일부 종목에만 있는 다음 날짜는 반영을 미루고, 선택한 날짜까지 일관되게 저장한다. 실제 기준일과 미반영 종목은 진단에 남긴다.
3. 이 방식의 대체 날짜는 기존 저장 데이터의 마지막 날짜보다 새로워야 한다. 오래된 데이터를 재저장하면서 정상 갱신으로 위장하거나 날짜를 뒤로 돌리지 않는다.
4. 잘못된 개별 종목은 기존 이력을 보존하고 신규 추천 대상에서 빠지게 한다. 조정가격이 바뀌면 전체 이력의 날짜와 가격 일관성을 확인하고, 불완전한 재수집 자료는 섞지 않는다.
5. 95%를 확보하지 못하거나 자료가 7일보다 오래되면 전체 시장 갱신을 중단한다. 명시적으로 지정한 날짜를 확보하지 못하면 기존 게시 검증도 계속 실패한다.

이는 공급자의 최신 자료 부재 자체를 해결하는 것은 아니다. 충분히 확보된 하루를 통째로 버리는 문제를 해결하며, 지연된 자료를 최신 자료라고 표시하지 않는다. 같은 현상이 계속되면 공급원 대체 또는 검증된 보완 수집이 필요하다.

## 5. 시장별 배치와 DB

| 시장 | 정규장 개장 | 배치 예약 | 한국 시각 |
|---|---|---|---|
| 한국 | 09:00 KST | 평일 06:00 `Asia/Seoul` | 06:00 |
| 미국 | 09:30 ET | 평일 06:30 `America/New_York` | 서머타임 19:30 / 표준시 20:30 |

각각 `Daily Refresh KR`, `Daily Refresh US`가 실행된다. 시장별 수집·추론·검증·상태 저장·게시를 독립된 작업으로 수행한다. 월별 학습도 시장별 저장 작업으로 분리한다. 수동 `all` 실행은 공유 스냅샷의 동시 쓰기를 피하기 위해 순서대로 진행하되, 한국 실패로 미국을 건너뛰지 않는다. 한국 저장 뒤 미국이 실패해도 한국 저장을 취소하지 않으며, 이미 검증된 Pages 묶음을 게시한다.

공유 `pipeline-state`의 쓰기 잠금은 유지한다. 예약 시간이 달라도 다른 연구·복구 작업이 길어지면 대기가 생길 수 있다. [GitHub의 시간대 지원과 실행 지연 설명](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)에 따라 IANA 시간대를 사용했으며, 예약은 시작 시각의 보장이나 완료 시각의 보장이 아니다. 휴장일에는 실제 관측된 마지막 종가를 사용한다. 특별 개장 시각까지 자동으로 맞추는 거래소 달력은 이번 범위에 포함하지 않았다. 정규장 시각은 [NYSE](https://www.nyse.com/trade/hours-calendars), [KRX 안내](https://global.krx.co.kr/contents/GLB/01/0109/0109000000/guide_to_trading_in_the_korean_stock_market.pdf)를 기준으로 했다.

공유 상태를 쓰는 8개 워크플로에는 `queue: max`를 적용한다. GitHub 기본값은 대기 중인 작업 하나를 새 작업으로 교체해 취소할 수 있어, 시장별 예약과 연구 작업이 겹칠 때 누락될 수 있다. [공식 동시 실행 문서](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)의 지원 설정으로 최대 100개가 대기하도록 하고, 실제 쓰기는 한 번에 하나만 수행한다. 대기 시간 자체를 없애는 변경은 아니다.

DB의 현재 상태는 다음과 같다.

- GitHub 실행 환경의 Oracle 연결로 한국 가격과 동결 모델의 압축 자료 **52,172,278바이트**를 체크섬 검증 후 복원했고, 기준일까지 가격 **3,125,975행**으로 재평가했다. 환경상 DB를 전혀 사용할 수 없는 상태가 아니다.
- 대화의 로컬 작업 환경에는 접속 설정이 없지만, 저장소에 설정된 실행 환경은 사용 가능하다. 인증값을 코드나 공개 로그에 넣을 필요가 없다.
- 운영의 기준 자료는 외부 백엔드의 검증된 스냅샷이다. 계산은 아직 CSV를 복원해서 수행한다. SQL 월별 적재는 앞선 이관 점검에서 34개월·1,620,394행까지 확인됐고, UNDO 부족으로 다음 적재가 막혔다. 이 수치는 그 점검 결과이며 이번 진단으로 현재 전체 적재량을 다시 센 것은 아니다.
- 이번에는 해당 시장의 SQL 적재만 큐에 넣고, 보조 SQL 적재 실패가 이미 저장한 예측의 게시를 막지 않도록 순서를 바꿨다. 기준 스냅샷 저장 실패는 여전히 게시를 막는다.
- 다음 DB 작업은 월 단위 대량 트랜잭션을 더 작은 재개 가능한 단위로 나누고, 부분 자료가 완성된 월로 노출되지 않게 한 뒤, 최신 가격 조회부터 SQL로 전환하는 것이다. 원본 파일·모델·장기 실험 자료는 객체 저장, 조회용 가격·작업 상태는 DB로 역할을 나누는 것이 현재 이관 경로에 맞는다. 실제 계정 용량·과금 상태는 이번 실행에서 확인하지 않았다.

[시장 파이프라인 검증](https://github.com/jaesung0804/st_dashboard/actions/runs/34566803516)과 [백엔드 상태 보존 검증](https://github.com/jaesung0804/st_dashboard/actions/runs/34566803446)이 통과했다. 겨울·여름 예약을 각각 변환해 정규 개장 3시간 전임을 확인했다. 실제 복구 실행 결과는 아래에 추가한다.

### 실제 실행에서 추가로 발견한 게시 장애

[첫 복구 실행](https://github.com/jaesung0804/st_dashboard/actions/runs/34567217783)에서 한국은 9월 10일까지 100% 수집했고 3,147,009행이 됐다. 그러나 별도 시뮬레이션 묶음의 `data_provenance.json` 체크섬 검사에서 멈춰 백엔드 저장 전 단계가 실패했다. 한국 실패 후에도 미국 작업이 시작되는 시장별 실행 분리는 확인했다.

Git에 저장된 원본 바이트의 SHA-256은 기존 매니페스트와 정확히 일치했다. 원본은 LF 줄바꿈 1,358개이며, Windows의 자동 CRLF 변환을 적용하면 해시가 달라진다. `.gitattributes`에서 완료된 `docs/replays/**` 자료의 줄바꿈 변환을 금지해 원본 그대로 검사하도록 수정했다. 체크섬을 새 값으로 덮어쓰거나 검사를 생략하지 않는다. 실제 Git을 `core.autocrlf=true`로 설정한 체크아웃 회귀 테스트도 통과했다.

또한 수집 스크립트 안에서 웹 묶음을 미리 조립하던 중복 호출을 제거했다. 시장별 수집·추론 결과를 검증하고 백엔드에 저장한 뒤 웹을 조립하는 바깥 단계만 남겨, 시뮬레이션이나 UI 오류 때문에 수집 결과까지 잃는 경로를 없앴다.
