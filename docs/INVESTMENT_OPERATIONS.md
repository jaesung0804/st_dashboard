# 투자 조직 운영조정팀

운영조정팀은 관찰된 작업 큐에서 막힌 원인과 다음 담당자를 찾는다. 로컬 Python 규칙으로 동작하며 외부 API, 유료 모델, 별도 Trello 계정 또는 상시 실행 서비스가 필요하지 않다. 검토 결과는 인계·우선순위·보고의 **추천**이며 실제 승인이나 메시지 전송 기록이 아니다. 현재 세션의 통합 담당 에이전트가 이를 확인하고 실제 업무와 연결한다.

| 가상 규칙 직원 | 담당 업무 | 권한 경계 |
| --- | --- | --- |
| 정태오 · OPS-LEAD | 우선순위, 상위 보고, 회차 경계 점검 | 투자·인사 승인권 없음 |
| 문예린 · OPS-FLOW | 의존 작업, 담당자별 진행 한도, 중복 작업 병합 제안 | 작업 인계가 승인권한 이전을 뜻하지 않음 |
| 백건우 · OPS-RELEASE | GitHub 준비·검증·발행 의존관계 추적 | 검증 생략, 강제 덮어쓰기, 유료 사용 승인 불가 |

정책은 `data/reference/investment_operations_policy.json`, 관찰 기록은 `data/reference/investment_operations_queue.json`에 있다. 이 초기 큐에는 완료된 53개 실험과 결과 감사, 진행 중인 GitHub 준비·전략 요약 개선, 운영팀 구축, UI 빌드·발행 및 해결되지 않은 역사 자료 문제를 기록했다. 각 상태는 기록된 실제 관찰 시점의 스냅샷이다. 과거 착수·승인 요청·완료 시각을 추정하지 않는다.

## 처리 규칙

1. 작업에는 담당자, 대체 담당자, 의존 작업, 우선순위, 기한, 다음 행동을 남긴다. 미등록 의존 작업과 순환 의존성을 차단 사유로 표시하고 가장 먼저 해결할 근본 작업을 찾는다.
2. 완료 상태는 출처와 실제 확인 시각이 있는 근거, 완료된 의존 작업, 통과한 필수 게이트가 있어야 유지한다. 근거가 없는 완료 주장은 차단 상태로 표시한다. 해결되지 않은 생존 편향·상장폐지 자료 문제도 마감 때문에 해제하지 않는다.
3. 투자 승인 요청에는 `strategy_brief`의 `thesis`, `entry`, `exit`, `horizon`, `risk`, `evidence_asof` 여섯 항목이 필요하다. 실제 전략 요약 생성기와 같은 필드 정의를 사용한다. 비어 있으면 요청자에게 보완을 요구한다. 승인권자는 별도로 정해져 있으며 운영 직원은 승인자가 될 수 없다.
4. 실제 승인 요청 시각이 기록되어 있고 15분이 지나면 기존 승인권한을 가진 대체 검토자로의 전달을 추천한다. 대기 시작 시각이 없으면 대기 시간을 `null`로 남긴다. 승인 대기시간이 길어져도 자동 승인하지 않는다.
5. 이미 사용자가 허락한 검증된 GitHub 결과물 발행은 그 허락의 범위 안에서 진행한다. 같은 허락을 반복 요청하지 않는다. 최종 검증이 미완료라면 허락이 있어도 발행 준비 상태는 차단된다.
6. 담당자별 진행 한도를 넘으면 능력과 여유가 있는 대체 담당자에게 인계를 추천한다. 여러 추천이 한 대체 담당자의 한도를 다시 넘지 않게 한다. 중복은 후보만 표시하고 원본 작업을 자동 삭제·병합하지 않는다.

투자 작업은 위험, 당시 정보, 수수료, 유료 사용 제한, 검증 게이트를 반드시 확인한다. 게이트를 생략하거나 `waived`로 쓰는 것은 통과가 아니다. 이 검토기의 근거 확인은 기록의 출처와 시각을 확인하는 것이며 가격·원장·산출물 해시를 검사하는 별도 검증기를 대신하지 않는다.

## 실제 1시간 회차

`data/reference/investment_rounds.json`이 실제 회차 기록이다. r03은 실제 UTC **2026-09-10 08:58:20**에 시작했고 예정 종료는 **09:58:20**이다. 한국 시각 17:58:20–18:58:20에 해당한다. 오늘 전체 업무 종료는 10:00 UTC, 한국 시각 19:00이다.

- 회차 길이는 과거 데이터 1시간이나 CPU 계산시간이 아니라 실제 업무시간 60분이다. 마감 전 온전한 60분을 확보할 수 없으면 새 회차를 시작하지 않는다.
- r03 시작 때 재직 중인 전략 직원 35명의 ID·이름·전략 계열을 고정했다. 김도현의 기존 퇴사 기록은 복원하지 않았다. 회차 중 신규 채용·퇴사는 불가하다.
- 위험 대응을 위한 운용 일시중단이나 자금 축소는 퇴사와 다르며 기존 투자 통제를 따라 처리한다. 회차 명단에서 삭제하지 않는다.
- 60분이 지난 후 회차를 종료하고, 종료 이후에 확인한 결과 검토 근거가 있어야 인사 검토 단계로 넘어간다. 이 단계도 인사 승인 자체는 아니다.
- 기존 53개 실험은 비교 기준이다. 새 회차 실험으로 다시 집계하지 않는다. 새 실험은 회차 시간 안에서 실행 전 프로토콜과 해시를 먼저 등록한다.

`investment_rounds.py`의 `start_round`, `register_experiment`, `validate_roster_lock`, `close_round`, `complete_results_review`, `personnel_timing_gate`가 이 경계를 검사한다. 함수가 시간을 기다리거나 백그라운드 작업을 시작하지는 않는다. 실제 시각·활동·검토 근거는 호출 담당자가 기록해야 한다. 회차 종료 후에도 인사 변경에는 기존 승인권한자의 결정이 필요하다.

## 실행과 통합

저장소 루트에서 실행한다.

```bash
python scripts/review_investment_operations.py --as-of 2026-09-10T09:05:00Z
python scripts/review_investment_operations.py --as-of 2026-09-10T09:05:00Z --output outputs/investment_operations_review.json
PYTHONPATH=src python tests/test_investment_operations.py
PYTHONPATH=src python tests/test_investment_rounds.py
```

`--as-of`를 생략하면 호출 순간의 실제 UTC를 사용한다. 같은 입력과 같은 시각은 같은 JSON을 출력한다. 검토기는 큐나 정책을 수정하지 않으며 출력 파일로 원본 큐·정책을 덮어쓰는 것도 거부한다. `simulation_clock`에는 과거 백테스트 날짜를 둘 수 있지만 업무 대기시간·기한 계산에 쓰지 않는다.

출력의 `tasks`에는 관찰 상태와 검토 상태, 승인 범위, 다음 담당자, 차단 원인, 근본 작업, 다음 행동을 담는다. `wip`, `dependency_cycles`, `duplicate_merge_suggestions`, `escalations`, `round_window`에서 조직 전체 병목과 남은 회차 시간을 볼 수 있다. `actions_executed`와 `approvals_created`는 항상 빈 배열이다.

실제 통합 담당자는 작업 진척이나 검증이 확인될 때 원본 큐의 관찰 시각·근거를 갱신한 뒤 검토기를 호출한다. 회차 정보는 별도 회차 파일의 실제 시작·종료·검토 근거를 `round_context`로 복사해 동기화한다. Trello나 대시보드는 이 관찰 시점을 함께 보여줘 오래된 상태를 실시간 관찰처럼 표시하지 않는다.

권한 우회, 의존성·순환, 출처 없는 완료, 실제/모의 시계 분리, 과다 인계 방지, 회차 길이, 명단 잠금, 새 실험 등록 경계 및 회차 종료 후 검토를 검증하는 12개 테스트가 통과했다. 실제 전략 요약을 운영 승인 요청에 연결하는 회귀 검사도 포함한다.
